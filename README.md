# Migration Control Tower — website

A cinematic, editorial presentation of the Autonomous Data Migration Control Tower,
built from the project's own artifact archive.

## Run it

```bash
npm install
npm run dev
```

Then open http://localhost:3300.

```bash
npm run build && npm run start   # production
npm run assets                   # regenerate media from the artifact archive
```

> **Don't run `npm run build` while `npm run dev` is running.** Both write to
> `.next`, and the build overwrites the dev server's client chunks, which breaks
> hydration until you `rm -rf .next` and restart.

## Deployment

Live: <https://migration-control-tower-nikhils-projects-50c91a6e.vercel.app>

Hosted on Vercel, linked to this repository. **Every push to `main` deploys to
production automatically** — there is no manual deploy step.

`npm run assets` is deliberately *not* part of the build. The build host has no
ffmpeg or Pillow, so everything under `public/media` is committed and
`npm run build` is all Vercel runs.

### The production domain

Never hardcoded. `src/lib/siteUrl.ts` resolves it, and `metadataBase`, the
sitemap and robots.txt all read from there:

1. `NEXT_PUBLIC_SITE_URL` if set — use this when a custom domain is added.
2. `VERCEL_PROJECT_PRODUCTION_URL`, injected by Vercel. This is always the
   *production* domain even during a preview build, so preview deployments never
   advertise themselves as canonical.
3. `http://localhost:3300` locally.

To attach a custom domain: add it in the Vercel project, then set
`NEXT_PUBLIC_SITE_URL` to it in the project's environment variables.

## What you need to fill in

Everything below is a one-file edit. No layout work is required.

### 1. Team portraits — **the only outstanding item**

Names, roles, bios and LinkedIn URLs for both members are already in
`src/data/team.ts`. Only the two photos are missing:

```bash
cp /path/to/nikhil-photo.jpg  assets-src/team/nikhil.jpg
cp /path/to/mousmi-photo.jpg  assets-src/team/mousmi.jpg
npm run assets
```

The filename must match the member's `id`. The pipeline EXIF-rotates each photo,
crops it to 4:5 biased toward the top of the frame (heads sit high), writes WebP
at 1200px and 600px, and records it in the generated manifest.

**No code change is needed afterwards.** `<Team>` looks each member up in that
manifest, so a member with no photo renders a composed placeholder and never
requests a file that is not there — which is also why `/about` logs no console
errors while the slots are empty.

### 2. Devpost URL — `src/data/site.ts`

```ts
devpost: "",   // paste the Devpost submission URL
```

An empty string renders as dimmed "coming soon" metadata rather than a dead
link, in the footer, the fullscreen menu and `/contact`.

### 3. Deploy domain — `src/app/layout.tsx` and `src/app/sitemap.ts`

Both use `https://migration-control-tower.example` as a placeholder. Replace with
the real origin so Open Graph URLs and the sitemap are correct.

## Architecture

```
src/
├── app/                 one route per page, all statically prerendered
├── components/
│   ├── shell/           AppShell, Header, FullscreenMenu, PageTransition,
│   │                    Loader, CustomCursor, Footer
│   ├── ui/              Type, AnimatedLink, Media, Metric, Marquee,
│   │                    NextPage, Section
│   └── sections/        HeroScrollFilm, PageHero, FilmSequence,
│                        ArchitectureFlow, HorizontalShowcase,
│                        EditorialAccordion, StatePath, TechStack,
│                        GuideChapters, Team
├── data/                all copy and content, no prose in components
├── hooks/               useReveal, useSplitLines, useParallax, useRevealImage,
│                        useCounter, useMarquee, useMagnetic, useMediaQuery,
│                        useFrameSequence
├── lib/                 motion tokens + GSAP registration, format, cx
└── providers/           SmoothScroll (Lenis on the GSAP ticker)
```

Content lives in `src/data/*`, taken from the artifact archive's content pack,
architecture brief and screenshot guide. Components contain no copy, so the site
can be re-worded without touching layout.

`src/data/media.ts` is generated by `scripts/prepare-assets.mjs` — do not edit it
by hand. It carries intrinsic dimensions for every asset so `next/image` never
causes layout shift.

## Live console access

`src/data/site.ts` carries the deployed console URL and the shared demo account
(`consoleDemo`). `<ConsoleAccess>` renders them with copy buttons on `/guide` and
`/contact`.

> These credentials are published on a public page by design, so a reviewer can
> open the running system without being provisioned an account. Two things to be
> aware of: the account holds the **operator** role, which is not read-only, and
> the project's own screenshot guide advises never publishing a real password.
> If that trade stops being worth it, either narrow the account to `viewer` or
> clear `consoleDemo` — the block disappears cleanly when the values are empty.

## Adding media that is not in the archive

`../shareed-artifacts-for -website/` is the original export and is treated as
read-only. Anything sourced later — a video generated in OpenArt, say — goes in
`assets-src/` instead.

1. Drop the file in `assets-src/film/`.
2. Add it to the `EXTRA_FILMS` table in `scripts/prepare-assets.mjs` as
   `[slug, filename, posterAtFraction]`. The poster fraction matters: pick a
   moment that represents the shot, not frame 0.
3. `npm run assets`, then reference it by slug, e.g. `<PageHero film="agent-fleet" />`.

> Run `npm run assets` without piping to `head` — a SIGPIPE kills it before it
> writes `src/data/media.ts`, leaving transcoded files with no manifest entry.

## Design tokens

All colour, type, spacing and motion values are CSS custom properties in
`src/app/globals.css`. Sections opt into a ground with `data-surface="dark"` or
`data-surface="paper"`, which flips the whole token set — so a component works on
either without knowing which it is on.

One accent, `#4DCCBE`, sampled from the project's own agent glyphs.

## The hero

The hero is one unbroken live-action shot — a push down a legacy data-centre
aisle that is tangled and unlit for five seconds, then reveals an ordered estate
as the fluorescents switch on in sequence. **Scroll drives that timeline.**

It is a one-way arc, which is exactly why it must not loop: the visitor performs
the reveal rather than watching it repeat. Everything else is bound to the same
0→1 progress value — the headline swaps as the lights come up, the state label
steps `UNMAPPED → DISCOVERING → GOVERNED`, the timeline rail fills, and the two
links only appear once the estate is visible.

**It is a canvas frame sequence, not a `<video>`.** Seeking a video against
scroll is unreliable across browsers, and encoding one seekable enough
(all-intra H.264) measured 5.5 MB. 96 decoded WebP frames measure 2.9 MB and
scrub with zero seek latency anywhere. Frames load in two passes — every 8th
first, so the whole arc is scrubbable almost immediately, then the rest fills in
and the picture sharpens.

Copy for each phase lives in `src/data/hero.ts`.

Below 1025px, or under `prefers-reduced-motion`, the hero falls back to the film
playing through once in the reading flow. **That branch is chosen in CSS**
(`.hero-scrub` / `.hero-static` in `globals.css`), not in JS state, so the server
renders the correct one and there is no swap on first paint — while the static
branch's copy still ships in the HTML for crawlers and no-JS readers.

## Motion

GSAP + ScrollTrigger own all scroll and cinematic animation; Lenis provides
smooth scrolling, driven by the GSAP ticker so the two never fight for rAF.
Durations and easing come from `src/lib/motion.ts` — no component invents its own
timing.

Three tiers, via `gsap.matchMedia`:

| Tier | Behaviour |
|---|---|
| Desktop ≥1025px | Full choreography: pinned film sequence, horizontal fleet, parallax, custom cursor |
| Tablet ≤1024px | Reveals and hovers only — no pinning, no horizontal scroll |
| Mobile ≤860px | Vertical storytelling, native scrolling, no cursor, no parallax |
| `prefers-reduced-motion` | Everything static and fully visible; Lenis disabled |

Elements are hidden only once JS confirms it can animate them (`data-motion-ready`),
so a script failure, a background tab, or reduced motion all leave a fully
readable page rather than a blank one.
